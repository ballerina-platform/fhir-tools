# ${label} FHIR facade

A Ballerina FHIR facade generated from **${ig}**, with the implementation guide's profiles carried as a
module so the API is typed against them.

Each FHIR resource type is served at `/fhir/r4/<ResourceType>` — for example
`http://localhost:9090/fhir/r4/Patient`.

## Run it

Needs **Java 21 or newer**, and nothing else — the jar carries the Ballerina runtime with it.

```bash
java -jar ${project}/target/bin/${jar}
```

The service starts on **port 9090**. Try it with:

```bash
curl -i http://localhost:9090/fhir/r4/Patient
```

Expect **`501 Not Implemented`**. That is the point of a facade: the routing, the FHIR request and response
handling, and the profile types are generated for you, and the resource functions are left as stubs for you to
fill in. Until you do, every operation answers 501.

## Change it, then rebuild

Open the project in **WSO2 Integrator**. It ships a Ballerina distribution inside, so there is nothing else to
install and no separate CLI to set up — editing and building both happen in the one application.

### 1. Install WSO2 Integrator

Download the installer for your operating system from the
[WSO2 Integrator v5.0.0 release](https://github.com/wso2/product-integrator/releases/tag/v5.0.0), then:

- **macOS** — run the `.dmg` and drag the application to **Applications**.
- **Windows** — run the `.msi` installer and follow the wizard.
- **Linux** — install the `.deb` (Ubuntu/Debian) or `.rpm` (RHEL/Fedora), or extract the `.tar.gz`.

Full instructions, including signing in on first launch, are in the
[local setup guide](https://wso2.com/integration-platform/docs/get-started/setup/local-setup).

### 2. Open this project

Open the **`${project}`** folder — the one containing `Ballerina.toml`. Opening the top folder of this archive
instead will not be recognised as a project.

### 3. Make your changes

The stubs are in `${project}/service.bal`, one per operation, each marked with a `TODO`. Implement the ones you
need — read from your own store, call a back-end, whatever the integration requires. Integrator edits the same
files on disk either visually or as source, so you can move between the two freely.

### 4. Build

Use the **Build** button in the Integrator UI. It uses the Ballerina distribution that ships with Integrator, so
the result is the same jar as the one above:

```
${project}/target/bin/${jar}
```

Run it with the `java -jar` command in **Run it**, or start it from Integrator directly.

> This project targets Ballerina **${distribution}**. If you already have a matching Ballerina CLI installed,
> `bal build` in the `${project}` folder does the same thing.
